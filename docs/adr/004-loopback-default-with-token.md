# 004 — 默认只监听回环地址，非回环强制令牌

状态: 已采纳 (2026-10)

## 背景

原实现 `serve({ ..., hostname: "0.0.0.0" })` 且**没有任何鉴权**。`/api/file`、
`/api/exec`、`/ws/terminal` 全部对局域网开放——同一 Wi-Fi 下任何设备都能读写工作区、
执行命令。这在手机上尤其危险：手机频繁切换网络，咖啡店/宿舍 Wi-Fi 下即是暴露状态。

## 选项

1. **默认回环 + 非回环令牌** — 本机浏览器（手机 Chrome 访问 `localhost`）无感；跨设备访问需要令牌。
2. **默认回环，完全不支持跨设备** — 最安全，但用户就无法从电脑访问手机上的工作区。
3. **保持 0.0.0.0，加令牌** — 默认仍需令牌，手机本机访问也要过一道，体验变差。

## 决定

采纳选项 1。

## 实现

- 默认 `POCKETD_HOST=127.0.0.1`。回环来源（`127.0.0.1` / `::1` / `::ffff:127.0.0.1`）直接放行。
- 设 `POCKETD_HOST=0.0.0.0` 时，非回环请求必须带令牌：`X-pocketd-Token` 头、`Authorization: Bearer`、
  `?token=` 查询参数，或 `pocketd_token` Cookie（旧的 `zcode_token` 仍被接受一次）。
- 浏览器首次用 `?token=` 访问时下发 `HttpOnly; SameSite=Lax` Cookie，后续免带参数。
- 令牌首次运行随机生成（32 字节 base64url），存 `~/.pocketd/state/secrets.json`（0600），
  Settings → 访问令牌可复制。
- `/api/auth/token` 仅回环可读（用于 UI 展示），非回环返回 403。
- 终端 WebSocket 的 upgrade 走同一套校验。

## 后果

- 从电脑访问手机需要显式设置 `POCKETD_HOST=0.0.0.0` 并复制令牌，多一步操作。
- `GET /api/config` 仍返回 `***` 掩码值表示"已配置"，不改变既有前端契约。
- 已被审计指出但**本次未做**的项：没有限流、没有登录失败锁定。令牌是 256 位随机值，
  在局域网场景下暴力枚举不可行，但公网暴露（不建议）需要额外的限流层。
